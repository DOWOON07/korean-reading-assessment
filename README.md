# 한국어 읽기평가 연구용 프로토타입 v0.15 (데모)

아동부터 성인까지의 한국어 읽기평가 흐름을 시험하는 웹 프로토타입입니다.

첫 화면의 경로 카드(A~D)는 핵심 후보와 선택형 연구 확장을 구분합니다. A는 낱말 읽기와 음운·글자-소리, B 기본은 45초 낱말 읽기와 연결글 낭독, C 기본은 어휘·문장·듣기 이해, D 기본은 사실·추론입니다. 한국어 규준이 없는 ROAR/TOSREC 계열, 형태소, 고차 문해 과제는 연구자가 명시적으로 켰을 때만 실시되고 핵심 점수와 분리됩니다.

| 경로 | 모듈 | 방식 |
|---|---|---|
| A | 단어 해독 | 소리 내어 읽기 → 음성인식 자동 채점 |
| A | 글자·소리 처리 (음운인식, 글자-소리 대응) | 듣고 보기 고르기 |
| B | 읽기 유창성 | 45초 낱말·지문 낭독 → 음성인식 자동 채점 |
| B 연구 확장 | 단어·비단어 판단, 문장 참·거짓 (ROAR·TOSREC 형식) | 기본 OFF, 핵심 점수와 분리 |
| C | 언어 이해 (어휘, 문장 듣기, 이야기 듣기) | 듣고 보기 고르기 |
| C 연구 확장 | 합성어·파생어 결합/분해 | 기본 OFF, 핵심 점수와 분리 |
| D | 글 이해 (사실·추론) | 글 읽고 보기 고르기 |
| D 연구 확장 | 평가·판단, 두 글·출처 평가 | 기본 OFF, 핵심 점수와 분리 |

녹음 없는 모듈의 문항은 `battery.js`, 문항 출처·선정 규칙은 `item-bank.js`, 자동 근거 감사는 `evidence-engine.js`에 있습니다. v0.15의 판단과 한계는 [근거 행렬](docs/V0_15_EVIDENCE_MATRIX_KO.md)에 있습니다. 듣기 문항은 한 세션 안에서 선택한 한국어 합성 음성을 고정하고 음성명·속도·실측 재생시간을 저장하지만, 고정 음원 등록 전에는 기기 사이의 동일 음성을 보장하지 못합니다.

> 이 프로그램은 연구용 시제품입니다. 난독증 진단, 표준점수, 백분위 또는 전문가 검사와 같은 판정을 제공하지 않습니다.

## 바로 실행하기

별도 설치나 빌드가 필요 없는 정적 웹앱입니다.

1. 저장소를 내려받습니다.
2. 저장소 폴더에서 간단한 로컬 서버를 실행합니다.

```bash
npm start
```

3. 브라우저(Chrome 권장)가 <http://localhost:8080>으로 자동으로 열립니다. 열리지 않으면 직접 주소를 입력하세요. 끌 때는 터미널에서 `Ctrl + C`.

`npm start`는 Node만으로 동작하는 `server.mjs`를 실행하므로 Windows·Mac 모두 같은 명령입니다. Python이 있다면 `python -m http.server 8080`도 됩니다.

### 5분 시연 순서

1. 첫 화면 **예시 채점 기록 불러오기** → **전문 결과지**: 10개 층 결과지와 분석 문장, 신뢰구간, 채점 신뢰도를 바로 볼 수 있습니다. **인쇄 · PDF 저장**으로 A4 결과지를 만듭니다.
2. **새 검사 시작** → 참여자 코드 입력 → 마이크 점검 → 짧은 선별검사 → 경로 화면(A~D, 선별 추천). 단어 해독과 유창성은 녹음하고, 선택한 핵심 후보 과제가 이어집니다. 연구 확장은 정보 입력의 연구자 설정에서 켠 경우에만 추가됩니다.
3. 검사가 끝나면 기다리지 않고 **참여자용 결과 보기**. 녹음 자동 분석은 **연구자 자동 분석**에서 명시적으로 시작하고, 사람 채점과 자동 채점의 일치도를 검증합니다.

마이크 기능은 보안상 `localhost` 또는 HTTPS 주소에서 실행해야 합니다. HTML 파일을 더블클릭해 `file://`로 열면 브라우저에 따라 마이크가 작동하지 않을 수 있습니다.

## GitHub Pages로 공개하기

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더 안의 파일 전체를 저장소 최상위에 올립니다.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Deploy from a branch**, `main`, `/ (root)`를 선택해 저장합니다.
5. 생성된 HTTPS 주소로 접속합니다.

GitHub Pages는 프로토타입을 보여주고 한 기기에서 시험하는 용도에는 적합합니다. 여러 기기에서 연구자료를 모으려면 별도의 서버와 접근 권한 관리가 필요합니다.

## 0.15에서 추가된 재현성·실시 품질·분석 기반

- **문항 근거 자동 감사:** 실제단어의 음절·받침·국립국어원 어휘등급과 KoFREN 41M어절 자발화 빈도, 비단어의 공식 어휘 충돌·짝 문항 일치, 지문의 길이·어휘등급 가용률·문법 표지, 선택지 정답 중복·길이 단서를 자동 기록합니다. 이 결과는 사전필터이며 타당도 판정이 아닙니다.
- **A 비단어 재설계:** 국립국어원 2023 기초어휘 전체표와 충돌하지 않는 후보로 바꾸고, 실제단어와 음절 수·받침 수·음운규칙을 문항별로 짝지었습니다. 공식 37,720개 고유 표제어로 철자 음절 bigram을 계산해 희귀 배열을 표시합니다. 발음 말뭉치 기반 음운확률과 파일럿 문항통계는 아직 대기입니다.
- **B 병렬형과 45초 제시 유효성:** 1~3등급을 각 20개씩 포함한 A/B/C 세 목록을 참여자 코드로 재현 가능하게 배정합니다. 60개가 5열×12행으로 모두 보이는지, 창 이탈·스크롤·크기 변경이 없었는지, 실제 종료시간이 45초±250ms인지 기록하며 실패한 실시를 점수에서 제외합니다.
- **화면 폭 행렬 검사:** 실제 headless Chrome/Edge로 320·768·1440 CSS px에서 60개 전체 가시성, 5열×12행, 가로 넘침 없음이 자동 검사됩니다.
- **파일럿 분석 도구:** 내보낸 세션에서 문항 난이도, 수정 문항-총점 상관, 가능한 경우 Cronbach α, 연령구간별 원시 난이도 차이를 계산합니다. 마지막 값은 DIF가 아니라 다음 검토 우선순위입니다.
- **TTS·ASR 벤치마크 게이트:** TTS 후보의 역전사·분당 음절·클리핑·청취 승인, 공개 한국어 음성자료의 CER/WER/RTF 비교를 같은 형식으로 처리합니다. 고정 음원은 아직 0개이며 빈 manifest를 READY로 오인하지 않습니다.
- **버전 추적:** 앱 `0.15.0`, 문항 `item-evidence-0.2`, 검사 사양 `assessment-spec-0.4`, 신규 세션 스키마 `0.5`를 기록합니다.

## 0.9에서 추가된 검사 역할 분리

- **B 한국어 중심 기본값:** 연결글 낭독을 기본 유창성 후보로 두고, 350ms 단어·비단어 판단과 문장 참·거짓은 `디지털 읽기 연구 확장`으로 기본 OFF 처리했습니다.

- **A 청사진 게이트:** 실제/비단어 × 일치/음운변동 균형을 감사하고, 문헌·공식자료 공학 뒤에도 파일럿·DIF·규준 전에는 후보로 기록합니다.

## 0.8에서 추가된 참여자 중심 UI·성능 분리

- **쉬운 첫 화면:** `내 읽기 모습을 알아봅니다`와 `읽기 확인 시작`으로 목적과 행동을 명확히 했습니다.
- **참여자/연구자 분리:** 환경 기술값, 무작위 순서, 도움조건, 문항 ID·비음화·비단어를 참여자 기본 화면에서 숨겼습니다.
- **선택형 화면 보정:** ID-1 카드, 100 mm 자, 보정 없이 진행 중 하나를 고릅니다.
- **ASR 완전 지연 실행:** 환경·마이크·A/B·완료 화면에서 Whisper를 자동 실행하지 않습니다. 연구자가 요청할 때만 small 모델부터 분석합니다.
- **연습 경계:** 연습에만 일관된 정오 피드백을 주고, 별도 `연습 끝 / 본검사 시작` 화면 뒤 본검사를 시작합니다.
- **B 첫 자극/키보드 수정:** 시작 버튼 전에는 첫 시간제한 자극을 보이지 않고, F/J 키의 스크롤 이동을 차단합니다.
- **녹음 재생 보강:** 저장 원음은 바꾸지 않고 사용자 재생만 기본 1.6×로 들을 수 있습니다.
- **TTS 후보 기준:** SunHi→InJoon을 우선하되 엔진 0.9×가 아니라 실측 220–280 SPM과 3개 청취평가로 후보를 통과시킵니다.
- **쉬운 결과:** 참여자용 요약을 기본으로 열고 전문 결과는 연구자 탭으로 분리했습니다.
- **연령 해석 보류:** 근거 없는 연령별 속도 자동분기를 제거하고 연령은 연구 분석 변수로만 저장합니다.

## 0.7에서 추가된 실시 안정성·HCI 관리

- **참여자 우선 첫 화면:** 검사 시작을 하나의 주 행동으로 두고, A~D 시연·결과지·검증은 접힌 검사자 도구로 분리했습니다.
- **화면 사전점검:** 85.6mm 기준 카드로 CSS px/mm를 보정하고, 약 50cm 시거리와 화면 배율 유지 확인을 세션에 저장합니다.
- **A 검사 렉 방어:** 검사 중에는 녹음 저장만 합니다. v0.8부터 종료 뒤 자동 실행도 없애 연구자 요청 때만 분석합니다.
- **이중 버퍼링:** 다음 두 선택형 화면의 DOM을 유휴 시간에 미리 만들고, 두 프레임 워밍업 뒤 노출 시간을 측정합니다.
- **지연 근거:** Long Task와 제시 직전 프레임 간격을 기록해 체감이 아니라 데이터로 렉을 확인합니다.
- **TTS 전환 구조:** 검증된 고정 음원을 우선하는 manifest를 추가하고, 아직 음원이 없을 때는 Natural/Neural 계열 한국어 기기 음성을 우선하는 잠정 대체를 명시합니다. 재생 속도는 WPM과 한국어 SPM을 함께 기록합니다.
- **TTS 후보 검증:** 연구자 도구에서 같은 문장으로 한국어 음성을 비교하고 자연스러움·명료도·속도 적절성을 평가해 다음 검사 음성으로 고정합니다.
- **동적평가 후보:** D 글 이해 뒤 L0 무도움, L1 핵심 문장 표시, L2 문장 분절·음성 조건을 별도 실시합니다. 동형 후보와 조건 순서를 균형화하고 기본 점수와 합치지 않습니다.
- **ASR 검증 자동화:** 사람 전사·판정을 입력하면 결과지에서 CER, WER, RTF, 정오 일치율과 Cohen's κ를 계산합니다.
- **버전 단일 기준:** 화면·세션·패키지가 `version.js`의 `0.7.0`을 사용합니다.

세부 전후 비교와 미완료 실증 항목은 [v0.7 전후 비교](docs/V0_7_UPDATE_BEFORE_AFTER_KO.md)에 있습니다. 직접 확인할 메뉴·절차·합격 기준은 [v0.7 로컬 검증 매뉴얼](docs/V0_7_VERIFICATION_MANUAL_KO.md), UI·TTS·ASR·시간 제시·비계 설계의 근거와 한계는 [v0.7 설계 근거서](docs/V0_7_DESIGN_RATIONALE_KO.md)에 정리했습니다.

## 0.6에서 추가된 측정 품질 관리

- **검사 사양 중앙화:** `assessment-spec.js`가 자극 글꼴·크기·행간, 350ms 노출 허용 오차, TTS 속도와 음성 선택 정책을 버전으로 관리합니다.
- **실제 제시시간 기록:** 350ms 단어 재인은 첫 paint부터 마스킹까지 `performance.now()`로 측정합니다. 목표보다 60ms 넘게 늦은 문항은 응답을 보존하되 `PRESENTATION_INVALID`로 표시해 점수·반응시간 통계에서 제외합니다.
- **다음 문항 사전 준비:** 현재 문항을 푸는 동안 다음 문항의 텍스트와 고정 보기 순서를 미리 계산하고 준비 선행시간을 저장합니다.
- **음성 재현 정보:** 세션에서 한국어 음성을 고정하고 엔진, 음성명, 언어, 속도, 재생시간, 추정 WPM, 실패를 기록합니다. 음성 재생 실패 시 듣기 문항의 응답 버튼을 열지 않습니다.
- **지시문 듣기:** 녹음형·선택형 하위검사의 핵심 안내를 화면 텍스트와 음성으로 함께 제공합니다.
- **본검사 무피드백:** 정오 피드백은 연습 문항에만 나오며 본검사에는 표시되지 않는 정책을 단위 테스트로 고정했습니다.
- **기술 사양표:** 전문 결과지에 화면·배율·WebGPU, 검사 사양 버전, 자극 시간 편차, TTS 사용·실패를 자동으로 표시합니다.
- **ASR 검증 계산:** `tools/asr_benchmark.mjs`로 사람 축어 전사 대비 CER/WER, 문항 일치도·κ, real-time factor를 계산합니다. 실제 녹음 절차는 [ASR 검증 절차](docs/ASR_VALIDATION_PROTOCOL_KO.md)에 있습니다.

## 기존 데모에서 구현된 것

- **검사 분량:** 정보 입력 화면에서 데모(선별 단어 4·해독 8문항·지문 1편, 약 5분)와 전체(8·16·2)를 고릅니다.
- **짧은 선별검사:** 단어(2×2)와 문장 낭독 1편을 참여자가 혼자 읽고 시스템이 자동 채점합니다. 결과로 실시할 모듈(A 단어 해독, B 유창성)과 모듈 안에서 중점 확인할 것(음운변동 규칙, 비단어 해독, 속도 등)을 추천하고, 검사자가 조정할 수 있습니다. 기준값은 파일럿 전 임시값입니다(`SCREENING_CONFIG`).
- **화면 이동:** 브라우저 뒤로·앞으로 버튼, 화면마다 '← 뒤로', 검사 중 나갈 때 확인, 새로고침 후 복귀. 검사 중에는 전체 단계·진행률·남은 시간을 표시합니다.
- **플랫폼 흐름(A~D 경로):** 브리핑 v1.2의 네 경로와 하위검사를 경로 화면에 보여 주고, 핵심 두 모듈 뒤에 나머지 하위검사 화면을 차례로 둘러볼 수 있습니다(`catalog.js`). 둘러보기 화면은 채점·저장하지 않습니다.
- **전문 결과지(`report.js`):** 브리핑 8장의 10개 층(검사 품질, 핵심 요약, 5영역 프로파일, 하위검사, 오류 프로파일, 수행 효율, 근거 추적, 규준 위치*, 변화 추적*, 해석 주의)과 부록(지표 정의와 근거). 두 핵심 모듈만 채우고 나머지는 “— 미실시” 공란입니다.
- **분석 문장:** 결과지의 각 층에 “관찰 → 해석 → 근거” 형식의 분석이 붙습니다. 모든 비율에 Wilson 95% 신뢰구간을, 조건 차이(실제단어−비단어, 일치−음운변동)에 Newcombe 신뢰구간을 붙이고, 구간이 0을 포함하면 차이를 주장하지 않습니다.
- **설계 근거서:** [docs/DESIGN_EVIDENCE_KO.md](docs/DESIGN_EVIDENCE_KO.md)에 설계 결정마다 구현 위치, 문헌 근거, 확인 수준을 적었습니다.

- **단어 해독:** 문항마다 허용 발음 목록(`accepted`). 전사를 입력하면 음절 위치별 오류 후보(대치·생략·삽입, 초성·중성·받침 차이)와 첫·최종 시도, 오류 사건 후보를 보여 주고 “후보를 판정 칸에 채우기”로 반영. 전사 규약: `/` 뒤는 다시 읽은 시도, `-`는 나누어 읽음.
- **읽기 유창성:** 지문 어절을 눌러 대치·생략·도움·보류, 자기수정·반복·삽입·긴 멈춤을 표시하면 정확도, 분당 정확 어절·음절, 첫 60초 값이 즉시 다시 계산됨.
- **파형:** 원음성 파형, 에너지 기반 발화 시작·끝 자동 추정, 시작·60초·종료 마커 드래그 수정(자동값과 수정값 모두 저장), 파형 클릭 재생.
- **반응 시작 시간:** 제시 시각과 녹음 안의 발화 시작으로 계산. 머뭇거림 창(3초) 초과 후보 표시.
- **시각이 있는 사건:** 재생 위치에 첫 오류·자기수정·반복 등을 기록하고, 오류→자기수정 간격을 자기수정 창(3초, 설정값)과 비교.
- **음절 단위 유창성:** 대치 어절에 실제 읽은 말을 적으면 음절 정렬로 맞게 읽은 음절만 인정.
- **문항 순서:** 단어 해독 본검사 무작위 옵션, 실제 제시 순서 저장.
- **기기 안 음성인식(연구자 요청 채점):** 브라우저 안에서 Whisper small을 기본으로 Transformers.js 3.8.1로 실행합니다. 원음성은 외부로 보내지 않고, 라이브러리와 모델만 처음 한 번 jsDelivr·Hugging Face에서 받아 캐시합니다. 참여자 흐름에서는 모델을 자동으로 받지 않습니다. large-v3-turbo는 별도 정확도 비교 조건에서만 선택합니다.
- **자동 채점 검증:** 연구용 검증 화면의 사람 채점과 자동 채점의 일치율·Cohen's κ.
- **채점 규칙 표:** 검토 화면에서 설계도 3.5·4.4 규칙을 펼쳐 볼 수 있음.
- **결과:** 실제/비단어 × 일치/음운변동 2×2 표, 문항별 근거 추적 표, 유창성 오류 지도.
- **예시 채점 기록 불러오기**(음성 없는 시연용 가상 채점값)와 원음성 포함 JSON 내보내기·가져오기.
- 채점 보조 계산은 `scoring.js`에 모았고 `tests/scoring.test.mjs`로 검사합니다. 규칙 수치(자기수정 창 3초 등)는 `SCORING_CONFIG` 설정값입니다.

## 자료 저장 방식과 개인정보 주의

- 참여자 이름 대신 `P-001` 같은 연구용 코드를 사용하세요.
- 세션 정보와 사람의 채점 결과는 브라우저의 `localStorage`에 저장됩니다.
- 음성은 브라우저의 `IndexedDB`에 별도로 저장됩니다.
- 서버로 자동 전송되지 않습니다.
- 브라우저 자료를 지우거나 다른 기기로 옮기면 기록이 보이지 않습니다.
- 중요한 기록은 JSON과 음성 파일로 내보낸 뒤, 연구계획에 맞는 암호화 저장소에 보관해야 합니다.

## 연구에서 지켜야 할 원칙

1. 현재 문항은 기능 시험용 후보입니다. 정답·난이도·동형성을 확정하지 않았습니다.
2. 두 학생 채점자의 일치는 `잠정 기준 자료`일 뿐 전문가 gold data가 아닙니다.
3. 두 채점자가 합의하지 못하면 `EXPERT_PENDING`으로 남기고 모델 학습 정답으로 쓰지 않습니다.
4. 문자열 편집거리는 전사 확인을 돕는 참고값이며 점수가 아닙니다.
5. 실제 참여자를 모집하기 전 연구윤리, 동의, 개인정보, 보관·폐기 절차를 확정해야 합니다.
