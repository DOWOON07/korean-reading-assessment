# v0.7 로컬 검증 매뉴얼

> 대상: 연구용 프로토타입 v0.7.0 작업 트리  
> 비교 기준: v0.6.0 로컬 체크포인트 `b01d1d3`  
> 작성일: 2026-10-05  
> 중요: v0.7은 아직 커밋하거나 `origin/main`에 푸시하지 않았다.

## 1. 이 문서의 목적

이 매뉴얼은 다음 두 가지를 분리해서 확인한다.

1. **기능 판정:** 요청한 보호 장치와 화면이 실제로 구현되어 작동하는가?
2. **세션 판정:** 이번 기기·음성·문항으로 얻은 자료가 연구에 사용할 만큼 안정적인가?

예를 들어 350ms 자극이 너무 오래 표시된 문항을 자동으로 `PRESENTATION_INVALID` 처리했다면 **보호 기능은 합격**이다. 그러나 그 문항을 포함한 **검사 세션은 재실시 또는 제외 대상**이다. 두 판정을 섞지 않는다.

표시 뜻은 다음과 같다.

- `[ ]` 직접 확인 전
- `[x]` 코드와 자동검사에서 확인됨
- `통과` 기대 동작과 일치
- `경고` 기능은 동작하지만 연구 조건이 표준화되지 않음
- `실패` 구현 오류 또는 자료 손실 가능성이 있어 커밋 전 수정 필요

## 2. 시작 전 준비

### 2.1 서버 실행

VS Code 터미널의 PowerShell에서 다음을 실행한다.

```powershell
cd "C:\LDW\graduate_research\korean-reading-assessment"
npm start
```

브라우저에서 <http://localhost:8080>을 연다. 이미 8080 포트가 사용 중인데 이 주소에서 프로토타입이 정상적으로 열리면 기존 서버를 그대로 사용해도 된다.

기존 8080 서버를 확인한 뒤 종료하고 다시 시작하려면 다음 순서로 실행한다.

```powershell
$serverProcessId = (Get-NetTCPConnection -LocalPort 8080 -State Listen).OwningProcess
Get-Process -Id $serverProcessId
Stop-Process -Id $serverProcessId
npm start
```

페이지가 예전 모습이면 `Ctrl + Shift + R`로 강력 새로고침한다.

### 2.2 준비물과 시험 조건

- Chrome 또는 Edge 최신판
- 신용카드 또는 교통카드 한 장: 긴 변 85.6mm
- 마이크와 스피커 또는 헤드폰
- 실제 발화가 포함된 A 또는 B 검사 기록 한 건
- 가능하면 크기가 다른 화면 두 대, 또는 데스크톱 창 너비 1920/1366/768px 조건
- 기록용 메모: 아래의 `통과/경고/실패`와 관찰 내용을 적는다.

주의: 하단의 **이 기기의 연구자료 초기화**는 저장된 세션을 지운다. 필요한 자료를 JSON과 음성 파일로 내보내기 전에는 누르지 않는다.

### 4.2 환경·글자·반응형 확인

경로: `검사 시작` → 참여자 코드 입력 → 연령·데모 선택 → `검사 환경 확인으로 이동`

- [ ] 환경 확인 상단에 화면 크기와 배율이 보인다.
- [ ] `자극 글꼴`이 `Noto Sans KR · 준비됨`인지 확인한다.
- [ ] `기기 대체 글꼴 사용 가능`이면 기능은 동작하지만 표준화 조건은 `경고`로 기록한다.
- [ ] 대비가 `15.3:1`, 조작 영역이 `최소 44px`로 표시된다.
- [ ] 실물 카드 긴 변을 화면 막대에 대고 슬라이더를 조절한다.
- [ ] `50cm`와 `확대·축소 유지`를 체크하기 전에는 `환경 확인 완료`가 비활성인지 확인한다.
- [ ] 시력 상태와 소리 장치를 실제 조건에 맞춰 고른다.
- [ ] 녹음이 필요한 경로에서는 ASR 준비가 끝나거나 실패 상태가 확정되기 전까지 진행 버튼이 잠기는지 본다.
- [ ] 진행한 뒤 A 단어, A/B 지문, 선택형 보기에서 글자가 겹치거나 잘리지 않고 한글 획이 또렷한지 본다.

화면 크기 확인은 두 종류로 나눈다.

1. **실제 검사 확인:** 브라우저 배율을 100%로 맞추고 카드 보정 후 배율을 바꾸지 않는다.
2. **레이아웃 접근성 확인:** 별도의 임시 세션에서 창을 320 CSS px 수준까지 좁히거나 200~400% 확대해 가로 스크롤·겹침을 본 뒤, 실제 검사 전 100%로 되돌리고 다시 보정한다.

물리 크기 후보의 사용자 확인 항목:

- [ ] 단어 18mm가 한눈에 들어오되 과도하게 크지 않다.
- [ ] 지문 5.3mm와 행간 1.7이 줄을 잃지 않고 읽기 편하다.
- [ ] 보기 4.8mm와 행간 1.65가 선택지 비교에 충분하다.
- [ ] 지문은 왼쪽 정렬이고 한 줄이 지나치게 길지 않다.
- [ ] 아동·청소년·성인 각각에서 불편, 눈부심, 과도한 머리 이동이 없는지 기록한다.

이 세 크기는 **검증된 최종값이 아니라 파일럿 시작값**이다. 한 명이 편하다고 최종 확정하지 말고 대상 연령별 자료를 모은다.

### 4.3 TTS 후보 검증

경로: 첫 화면 → `검사자·연구자 도구` → `TTS 후보 검증`

- [ ] 한국어 음성 후보가 목록에 나타난다.
- [ ] `Natural`, `Neural`, `Premium`, `Enhanced`가 이름에 포함된 음성은 `고품질 후보`로 표시되는지 본다.
- [ ] 같은 공통 평가 문장을 후보마다 0.85×, 0.90×, 0.95×로 들어 본다.
- [ ] 발음 오류, 수사·고유명사 처리, 문장 경계, 억양, 잡음·끊김을 메모한다.
- [ ] 자연스러움·명료도·속도 적절성을 각각 1~5로 평가한다.
- [ ] 선택한 후보에서 `이 음성을 연구 후보로 고정`을 누른다.
- [ ] 아래에 음성명·속도·평정이 `현재 연구 후보`로 표시된다.
- [ ] 새 검사 환경 확인 화면에 같은 음성명과 속도가 표시된다.
- [ ] C 또는 D 듣기 문항에서 실제 재생되고, 결과지 TTS 열에 음성·WPM·SPM·실패 수가 남는지 확인한다.

판정:

- `통과`: 선택·평정·고정·재생·기록이 모두 이어진다.
- `경고`: 현재 `고정 음원 0개`는 정상 표시지만, 이는 기기 간 같은 소리를 보장하지 못한다는 뜻이다.
- `실패`: 한국어 음성이 있는데 목록이 비거나, 저장한 음성과 실제 사용 음성이 다르거나, 실패했는데 응답할 수 있다.

`고품질 후보` 표시는 음성 이름에 대한 우선순위 규칙일 뿐 품질 인증이 아니다. 최종 음성은 청취평가와 고정 음원 제작을 거쳐야 한다.

### 4.4 A 검사 렉과 ASR 후처리 확인

경로: 첫 화면 → `검사자·연구자 도구` → `A 글자·소리/해독`

1. 참여자 코드 `CHECK-A-01`, 데모를 선택한다.
2. 환경 확인에서 ASR 모델 준비 완료를 기다린다. 첫 실행은 모델 다운로드 때문에 오래 걸릴 수 있다.
3. 마이크 점검 후 낱말을 녹음한다.
4. `이 녹음 사용`으로 다음 문항에 여러 번 이동한다.
5. 마지막 선택형 자극까지 끝낸 뒤 완료 화면을 본다.

확인 항목:

- [ ] 문항을 저장할 때 `Whisper 분석 중` 표시가 뜨지 않고 다음 자극이 먼저 열린다.
- [ ] 다음 문항에서 반복적인 멈춤, 빈 화면, 클릭 무반응이 없다.
- [ ] 모든 자극이 끝난 **완료 화면에서만** `자동 채점` 진행률이 시작된다.
- [ ] 자동 채점 실패 시 녹음이 사라지지 않고 `다시 분석`이 제공된다.
- [ ] 결과지에서 사용한 Whisper 모델과 장치가 표시된다.

판정:

- `통과`: 검사 중 추론 경쟁이 사라지고, 후처리가 완료 화면으로 이동했다.
- `경고`: 완료 뒤 분석 대기시간이 길다. 이는 검사 중 렉을 줄이기 위해 선택한 교환 비용이다.
- `실패`: 각 녹음 직후 GPU/CPU 분석이 시작되거나, 녹음 저장·다음 화면 이동이 반복적으로 멈춘다.

### 4.5 B 검사 350ms 제시 품질 확인

경로: 첫 화면 → `검사자·연구자 도구` → `B 읽기 유창성` → 단어 자동성

- [ ] 단어/비단어가 잠깐 나온 뒤 가려지고 보기는 계속 응답 가능하다.
- [ ] 본검사에서는 정답/오답 문구가 나오지 않는다.
- [ ] 연속 문항에서 이전 단어나 이전 보기가 순간적으로 재등장하지 않는다.
- [ ] 검사 뒤 전문 결과지의 `제시 품질과 기술 사양`을 연다.
- [ ] `계측 문항`, `최대 지연`, `워밍업 프레임 최대`, `허용 +60ms`가 표시된다.
- [ ] 브라우저 지원 시 `long-task 계측 지원`이 표시된다.
- [ ] 지연이 +60ms를 넘은 문항은 `PRESENTATION_INVALID`로 남고 정답률·반응시간 집계에서 빠진다.

판정은 두 줄로 적는다.

- 보호 기능: 늦은 문항을 찾아 제외하면 `통과`.
- 검사 세션: 무효 문항이 0개면 `통과`; 1개 이상이면 원인 확인 후 해당 세션 재실시를 검토한다.

### 4.6 연습/본검사 피드백과 안내 확인

A 선택형, B 단어 자동성·묵독, C 또는 D 중 하나를 실시한다.

- [ ] 하위검사 시작 화면에서 글과 음성 안내를 함께 사용할 수 있다.
- [ ] 연습 문항에서 답을 고르면 정답 여부 또는 정답이 보인다.
- [ ] 본검사 문항에서는 정오가 표시되지 않고 다음 문항으로 이동한다.
- [ ] A/B 녹음 화면의 `검사자 추가 설명 기록`을 한 번 누른다.
- [ ] 결과지 TTS/기술 사양에 `추가 설명 1회`가 표시된다.

본검사에서 정답을 알려주면 다음 반응을 학습시킬 수 있으므로 `실패`로 본다.

### 4.7 D 경로 L0/L1/L2 분리 확인

경로: 첫 화면 → `검사자·연구자 도구` → `D 글 이해`

- [ ] 정보 입력 화면에서 `D 글 이해 뒤 L0/L1/L2 비계 반응 실험 포함`이 체크되어 있다.
- [ ] 기본 D 글 이해 문항이 먼저 실시된다.
- [ ] 이후 `추가 읽기 활동`으로 이동한다.
- [ ] L0는 도움 없이 읽기, L1은 핵심 문장 표시, L2는 문장 분절과 `나누어 듣기`로 구별된다.
- [ ] 세 조건이 같은 문항을 반복하지 않고 서로 다른 후보를 쓴다.
- [ ] 조건·후보 순서는 다른 참여자 코드를 썼을 때 회전한다.
- [ ] 각 응답 직후 정오 피드백이 나오지 않는다.
- [ ] 결과지 D 범위의 `지원 반응 · L0/L1/L2` 표에 조건별 결과와 반응시간이 보인다.
- [ ] 표 아래에 기본 글 이해 점수와 합치지 않는다는 경고가 보인다.

기능이 보여도 문항 동형성이 검증되지 않았으므로 L0 대비 향상을 곧바로 중재 효과로 해석하면 안 된다.

### 4.8 사람 기준 ASR 검증 확인

사전 조건: A 또는 B에서 실제 음성을 녹음해 완료한다.

경로: 첫 화면 → `검사자·연구자 도구` → `자동 채점 검증`

- [ ] 검사 기록에서 방금 만든 세션을 고른다.
- [ ] 원음성을 재생할 수 있다.
- [ ] Whisper 전사·후보와 원문을 나란히 볼 수 있다.
- [ ] 사람 축어 전사를 입력하고 채점 A를 저장한다.
- [ ] 같은 녹음을 독립적으로 채점 B에 저장한다.
- [ ] 두 판정이 다르면 합의 또는 `전문가 검토로 보류`가 가능하다.
- [ ] `전문 결과지 보기`로 이동한다.
- [ ] `자동 채점 검증`에 사람 전사 표본 수, CER, WER, RTF, 자동-사람 및 사람-사람 일치율·Cohen's κ가 보인다.

예시 자료만으로 지표가 그려지는 것은 계산 기능 확인일 뿐 모델 성능 검증이 아니다. 한국어 대상자 실제 녹음과 독립 채점 자료가 필요하다.

| 좁은 창/태블릿 폭 | 홈·선택형·검증 화면 | 열이 한 줄로 재배치되고 가로 스크롤 없이 주요 기능 사용 가능 | `[ ]` |
