# v0.10 문헌·공식자료 기반 검사 공학 근거서

## 결론

전문가 검토를 당장 받을 수 없는 조건에서 연구자가 할 수 있는 최선은 **이미 표준화된 검사를 복제했다고 주장하는 것**이 아니라, 공개된 공식자료와 연구문헌으로 문항 청사진·선정 규칙·출처·한계를 재현 가능하게 만들고 파일럿 자료로 남은 불확실성을 검증하는 것이다. v0.10은 이 원칙을 코드에 적용한 버전이다.

현재 결과물의 정확한 지위는 `문헌·공식자료로 공학된 연구 후보`이다. 내용타당도, 연령 규준, 절단점, 민감도·특이도, 검사-재검사 신뢰도는 아직 얻지 않았으므로 표준화 검사나 진단 도구라고 부르지 않는다.

## 사용한 자료와 역할

| 자료 | v0.10에서 사용한 범위 | 사용하지 않은 주장 |
|---|---|---|
| 국립국어원 「국어 기초 어휘 선정 및 어휘 등급화 연구」(2023), 공공누리 제1유형 | A 실제단어의 등급·품사·어종 확인, B 낱말 목록의 등급 층화·동형어 점검 | 어휘 등급을 읽기 난이도 규준이나 연령별 절단점으로 사용하지 않음 |
| 한국어 읽기 구성요인 연구의 45초 단어 읽기·1분 문단 읽기 형식 | B의 시간제한 낱말 읽기 실시시간과 원점수 형식 | 해당 연구의 표본 규준을 현재 사용자에게 직접 적용하지 않음 |
| AERA·APA·NCME 검사 표준 | 용도·청사진·출처·제한·해석 범위 명시 | 타당도를 문헌 인용만으로 완료했다고 주장하지 않음 |
| 형태소 인식 종단 연구 | C 형태소를 읽기 관련 연구 확장으로 유지하고 결합·분해 과제로 구성 | 형태소 점수를 핵심 언어이해 점수나 진단 점수에 합치지 않음 |

코드상 출처·목록·선정 규칙은 `item-bank.js`에 저장된다. 논문 제목만 문서에 적는 방식과 달리, 문항이 바뀌면 자동검사가 목록 수와 등급 균형을 다시 확인한다.

## A 단어 해독

### 유지한 구조

`실제단어/비단어 × 표기-발음 일치/음운변동`의 2×2 구조는 한국어 해독에서 어휘 지식의 도움, 낯선 글자열 해독, 음운규칙 적용을 분리해 보기 위한 합리적인 청사진이다. 네 칸에 같은 수의 문항이 들어가는지 코드가 검사한다.

### v0.10에서 강화한 부분

- 실제단어 8개에 국립국어원 2023 어휘 등급, 품사, 어종, 출처를 연결했다.
- 현재 8개는 모두 1등급 어휘다. 따라서 익숙한 실제단어 조건을 제공하지만 넓은 난이도 범위를 대표하지는 않는다.
- `모자`는 공식 목록에 동형어가 있어 주의 표식을 남겼다. 맥락 없는 낭독에서 의미 중의성이 수행에 영향을 주는지 파일럿에서 확인한다.
- 비단어는 아직 말뭉치 기반 음절·음소배열 확률을 완전히 맞춘 목록이 아니므로 `PENDING_CORPUS_PHONOTACTIC_AUDIT`로 저장한다.
- 상태값은 `LITERATURE_AND_OFFICIAL_DATA_ENGINEERED_PENDING_PILOT`이다. 전문가 검토가 불가능하더라도 파일럿 난이도·변별도·신뢰도·DIF 검증은 생략할 수 없다.

## B 읽기 유창성

### 왜 ROAR 계열만으로 대체하지 않았는가

350ms 단어/비단어 판단과 F/J 반응, TOSREC형 문장 참·거짓은 자동 재인과 묵독 효율을 정교하게 연구할 수 있다. 그러나 현재 한국어 연령 규준을 가진 국내 핵심검사는 아니다. 따라서 v0.9부터 `디지털 읽기 연구 확장`으로 유지한다.

### v0.10의 한국어 대안

핵심 후보에 `45초 낱말 읽기`를 추가했다.

- 국립국어원 2023 기초어휘 1·2·3등급에서 각각 20개, 총 60개를 선택했다.
- 모두 2음절, 명사, 일반어, 표준동형어번호 0인 항목으로 제한했다.
- 등급 오름차순으로 제시해 현재 목록의 재현성을 확보했다.
- 화면 폭이 달라도 순서가 바뀌지 않도록 5열 × 12행 고정 격자를 쓰고, 글자 크기만 뷰포트 폭·높이 안에서 제한적으로 조절한다.
- 45초가 되면 녹음이 자동 종료된다.
- 결과는 `45초 안에 정확히 읽은 낱말 수`와 `시도 낱말 수`로 연결글 결과와 분리한다.

이 선택은 임의 목록보다 낫지만 완성된 표준검사는 아니다. 국립국어원 등급은 일반 어휘 친숙도 자료이고, 실제 읽기 난이도는 자소-음소 일치, 받침, 음운변동, 음절빈도, 길이, 연령에 따라서도 달라진다. 다음 파일럿에서는 문항 위치에 따른 중단 효과, 등급별 정답률, 오류율과 반응시간을 확인하고 목록 순서를 재조정해야 한다.

## C 형태소 인식

### 왜 유지하는가

형태소 인식은 낱말 안의 의미 단위를 알아차리고 조작하는 능력이며 어휘·해독·읽기이해와 관련된다는 종단 근거가 있다. 특히 합성어와 파생어 구조가 풍부한 한국어에서 연구 가치가 있다.

### 왜 핵심검사는 아닌가

현재 구현에는 국내 연령별 규준과 증분타당도 자료가 없다. 핵심 언어이해를 어휘·문장·듣기 이해로 구성한 뒤, 형태소는 연구자가 켰을 때만 별도 실시하고 별도 보고한다.

### 무엇을 바꾸었는가

이전의 “같은 글자인데 뜻이 다른 것 찾기”는 동형어 지식, 한자어 지식, 어휘 친숙도가 섞여 형태소 조작을 직접 재기 어려웠다. v0.10은 다음 네 구성으로 교체했다.

1. 합성어 결합: `손을 닦는 수건 → 손수건`
2. 합성어 분해: `밤길 → 밤 + 길`
3. 파생어 결합: `풋- + 사과 → 풋사과`
4. 파생어 분해: `덮개 → 덮다 + -개`

각 유형은 2문항이며 정답률은 연구 확장 탐색값으로만 보고한다. 선택지 단서, 어휘 친숙도, 접사 생산성은 파일럿으로 확인해야 한다.

## 고정 음원·TTS

기기마다 다른 Web Speech 음성을 쓰면 같은 문항도 발음·속도·음질이 달라진다. 따라서 최종 운영은 고정 음원이 맞다. 다만 ‘좋아 보이는 TTS’를 코드가 자동 선택하는 것은 발음 타당도 검증이 아니다.

v0.10은 고정 음원 등록 규칙을 강화했다. 각 파일에는 음성 출처와 사용권, 문장 버전, SHA-256, 실측 길이, 표본화율, 발음 정확성·식별 가능성·속도·왜곡에 대한 청취 승인 기록이 모두 있어야 한다. `npm run check`가 이를 검사한다. 현재 manifest는 의도적으로 0개이며 상태는 `MANIFEST_READY_ASSETS_PENDING`이다. 따라서 현재 기기 음성은 잠정 수단이고, TTS 교체가 완료되었다고 표시하지 않는다.

전문가가 없을 때 가능한 절차는 다음과 같다.

1. 사용권이 명확한 한국어 음성 후보를 동일 대본으로 고정 파일화한다.
2. 연구자와 일반 청취자 여러 명이 발음 정확성, 목표 낱말 식별, 속도 적절성, 기계음·왜곡을 독립 평가한다.
3. 오인식이 있는 문항은 다시 합성하거나 녹음한다.
4. 통과 파일만 manifest에 `ACCEPTED`로 등록한다.
5. 이후 모든 참여자에게 같은 파일과 같은 음량 정규화를 사용한다.

## 파일럿에서 반드시 얻을 값

- 문항별 정답률, 문항-총점 상관, 선택지 기능
- A 네 조건의 신뢰도와 비단어 음소배열 적합성
- B 45초 목록의 위치별 도달률과 등급별 오류율
- C 네 형태소 유형의 난이도·변별도와 핵심 읽기 지표에 대한 증분 설명력
- 연령 집단별 측정 동일성 및 DIF
- 실제 기기별 자극 제시 지연, 녹음 품질, ASR CER/WER/RTF와 사람 채점 일치도

이 값은 문헌에서 대신 가져올 수 없다. 문헌·공식자료는 더 좋은 시작 문항을 만들고 과장된 해석을 막아 주며, 현재 프로토타입 자체의 타당도는 파일럿 자료로 쌓아야 한다.
