# v0.15 개발 결과: 문헌·공개자료 기반 보강판

작성일: 2026-10-06  
비교 기준: v0.10.0  
현재 앱: v0.15.0 / 문항 근거 `item-evidence-0.2` / 검사 사양 `assessment-spec-0.4` / 신규 세션 스키마 `0.5`

## 1. 결론

이번 개발은 새 검사를 임의로 더 붙이는 작업이 아니라, 기존 A~D 후보 과제를 **재현 가능하게 실시하고, 문항 선정 이유를 데이터로 남기고, 불량 실시를 점수에서 제외하고, 다음 파일럿 자료로 문항을 줄일 수 있는 구조**로 바꾸는 작업이다.

현재 코드로 완료된 것은 다음 네 가지다.

1. A 실제단어·비단어와 B 45초 낱말 목록의 기본 언어학적 조건을 자동 검사한다.
2. B 45초 검사가 어느 화면에서도 같은 목록 구조로 보였는지와 실제 45초를 지켰는지를 기록한다.
3. C·D 지문과 선택지의 기초 품질 문제를 자동으로 표시한다.
4. 실제 파일럿 자료가 들어오면 문항 난이도·변별도·내적 일관성과 집단 차이를 계산할 수 있다.

이것은 “표준화가 끝났다”는 뜻이 아니다. **문헌·공식자료로 통제할 수 있는 단계는 코드로 통제했고, 관찰자료가 필요한 단계는 측정 가능한 대기 상태로 만들었다**는 뜻이다.

## 3. 영역별 변경 결과

### A. 낱말 해독

이전에는 2×2 구조인 `실제/비단어 × 표기-발음 일치/음운변동`의 문항 수 균형만 확인했다. 지금은 다음을 함께 저장한다.

- 실제단어: 국립국어원 2023 기초어휘 등급·품사·어종, KoFREN 41M어절 자발화의 같은 품사 원빈도·조정빈도 log10, 음절 수, 받침 수
- 비단어: 공식 40,000 어휘 표제어 충돌 여부, 한글 음절 적법성, 짝 실제단어, 음절 수 일치, 받침 수 일치, 음절·자모 거리
- 음운변동 비단어: 짝 실제단어와 같은 규칙과 허용 발음

교체된 비단어는 `두버, 머자, 바너, 우덩, 덕문, 말논, 텥이, 덥한`이다. 8개 모두 기본조건을 통과한다. 국립국어원 40,000 목록의 37,720개 고유 표제어에서 add-one 평활한 단어경계 포함 철자 음절 bigram을 계산해 2음절 표제어 분포 내 백분위를 기록했다. `두버 4.85, 머자 42.36, 바너 14.12, 우덩 9.61, 덕문 10.51, 말논 4.63, 텥이 3.16, 덥한 1.65` 백분위다. 낮은 값은 자동 탈락선이 아니라 파일럿 난이도와 후보 교체를 먼저 살펴볼 순서다. 철자 배열 대리지표이므로 발음 말뭉치 기반 음운확률을 대신하지 않는다.

### B. 읽기 유창성

45초 낱말 읽기는 다음처럼 강화했다.

- 60개, 국립국어원 1~3등급 각 20개라는 같은 청사진으로 A/B/C 세 목록을 만든다.
- 각 행에 난이도가 한쪽으로 몰리지 않도록 5개 단위 등급 패턴을 고정한다.
- 참여자 코드를 해시해 목록을 배정하므로 같은 코드는 새로고침 뒤에도 같은 목록을 받는다.
- 검사 시작 전에 60개가 한 화면에 모두 보이고 5열×12행인지 검사한다.
- 시작 뒤 `performance.now()`로 실제 시간을 재고 45,000ms에서 자동 종료한다.
- ±250ms를 넘거나, 검사 중 창을 숨기거나, 크기를 바꾸거나, 스크롤하거나, 창 초점을 잃으면 제시 조건을 무효로 기록한다.
- 무효 실시의 녹음은 보존하지만 참여자 점수에는 0점으로 넣지 않고 “점수 제외”로 표시한다.

320·768·1440 CSS px의 headless Chrome/Edge 화면 검사에서 60개 전체 가시성, 5열×12행, 가로 넘침 없음이 통과했다.

### C·D. 선택형 언어·글 이해

`battery.js`의 각 절에 다음 자동 감사가 붙는다.

- 지문: 어절·음절·문장 수, 문장당 평균/최대 어절, 어절당 평균 음절, 연결어·내포·피동/사동·부정 표지
- 어휘: 현재 사전에 연결된 국립국어원 등급의 포함률
- 선택지: 정답이 보기 안에 정확히 한 번 있는지, 보기 중복, 정답만 지나치게 긴지, 보기 길이 차가 큰지
- 사실·어휘·문장구조 문항: 선언한 정답이 지문에 그대로 나타나지 않으면 검토 표시

이 감사를 통과했다고 좋은 문항이 되는 것은 아니다. 코드가 잡을 수 있는 형식 오류와 단서를 먼저 제거해, 사람이 의미·문화·교육과정 적합성을 검토할 범위를 줄이는 장치다.

### TTS와 고정 음원

선택 기준은 구현했지만 **실제 고정 음원은 아직 0개**다. 지금 기기 TTS는 시연 대체 수단이다. 다음 네 조건을 모두 만족한 녹음만 `tts-assets.js`의 고정 manifest에 넣을 수 있다.

1. 목표 문장과 ASR 역전사가 일치(CER 0)
2. 실측 220~280 SPM
3. clip ratio 0.1% 이하, peak -1 dBFS 이하
4. 청취 검토 `ACCEPTED`

따라서 “좋은 TTS로 교체 완료”라고 보고하면 안 된다. “후보를 동일한 조건으로 비교하고 불량 음원을 등록하지 않는 게이트를 완료했다”가 정확하다.

### ASR와 파일럿 분석

- 공개 한국어 자료: KsponSpeech, Mozilla Common Voice Korean을 모델 후보의 CER/WER/RTF 비교 자료로 등록했다.
- 대상 집단 자료: 내보낸 세션 JSON에서 제시 무효 자료를 제외하고 문항별 정오를 긴 형식으로 만든다.
- 기술 통계: 난이도 p, 수정 문항-총점 상관, 완전자료일 때 Cronbach α를 계산한다.
- 집단 감사: 연령 구간별 p 차이를 표시한다. 이것은 문항반응이론 DIF 검정이 아니라 표본을 더 살펴볼 우선순위다.

공개 일반음성에서 좋은 ASR도 읽기곤란 아동·성인의 낭독 자동채점에 타당하다고 바로 말할 수 없다. 공개자료는 모델 후보를 줄이고 실행시간을 비교하는 1단계, 실제 대상 집단 녹음은 최종 검증 단계다.

## 4. 자동 검증 결과

`npm run check` 한 번으로 다음을 실행한다.

- 모든 JavaScript 문법 검사
- 빈 TTS manifest를 READY로 처리하지 않는지 검사
- 화면·세션·저장·녹음·채점 상태 smoke test
- 버전 단일 기준 검사
- 연습/본검사 피드백, 자극 노출, 음성 선택, 렉 방어 검사
- 채점·신뢰구간·일치도 단위 검사
- A 문항 균형과 허용 발음 검사
- 핵심 후보/연구 확장 분리 검사
- 문항 근거, 비단어 짝맞춤, 병렬형, C 형태소 청사진 검사
- v0.15 근거 엔진·파일럿 통계 검사
- 320/768/1440 화면 폭 브라우저 검사

2026-10-06 현재 모든 항목이 통과한다. 고정 음원 검사는 `통과(대기): 고정 음원 0개`로 표시된다. 이는 실패를 숨기는 통과가 아니라, 빈 목록이 준비 완료로 승격되지 않았음을 뜻한다.

## 5. 현재 정확하게 말할 수 있는 것

- 문항 구조와 실시 조건은 코드로 재현 가능하다.
- A 실제단어·비단어의 기본 언어학적 조건과 실제단어의 자발화 빈도, B 목록의 등급 분포를 추적할 수 있다.
- 45초 실시가 화면·시간 조건을 지키지 않았으면 점수에서 제외할 수 있다.
- C·D 지문/선택지의 기초 형식 문제를 자동으로 찾을 수 있다.
- 공개 음성자료와 실제 파일럿 자료를 같은 지표로 분석할 도구가 준비됐다.

현재 말할 수 없는 것은 다음과 같다.

- 이 문항들이 한국인 아동·청소년·성인의 읽기 능력을 규준에 맞게 측정한다.
- 특정 점수로 읽기장애를 선별하거나 진단할 수 있다.
- A/B/C 병렬형의 난이도가 실제로 같다.
- 현재 브라우저 TTS가 모든 기기에서 같은 음성과 속도를 낸다.
- 공개 일반음성 성능이 목표 집단의 자동채점 성능과 같다.
