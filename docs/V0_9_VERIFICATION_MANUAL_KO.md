# v0.9 로컬 확인 매뉴얼

대상: `연구용 프로토타입 v0.9.0`  
목표: 기본 검사와 연구 확장이 실제로 분리됐는지 눈으로 확인한다.

## 1. 시작

프로젝트 폴더에서 `npm start`를 실행하고 `http://localhost:8080`을 연다. 이전 화면이 남아 있으면 `Ctrl+F5`로 새로고침한다. 상단과 첫 화면에 `연구용 프로토타입 v0.9.0`이 보여야 한다.

## 2. 첫 화면 카드

- B 카드: `핵심: 연결글 낭독 · 선택: 디지털 연구 과제`
- C 카드: `핵심: 어휘 · 문장 · 듣기 · 선택: 형태소`
- D 카드: `핵심: 사실 · 추론 · 선택: 평가 · 두 글 비교`

이 문구가 보이면 검사 역할 변경이 로컬에 반영된 것이다.

## 3. 기본값 OFF 확인

1. `검사자·연구자 도구`를 연다.
2. B 읽기 유창성을 누른다.
3. 참여자 코드·연령을 입력하기 전에 `연구자 설정`을 연다.
4. `B 디지털 읽기 연구 확장 실시`가 체크되지 않았는지 본다.
5. 그대로 검사를 시작하면 B에는 연결글 낭독만 들어가고, 350ms F/J 및 문장 참·거짓은 나오지 않아야 한다.

C와 D도 같은 방식으로 확인한다.

- C 기본: 어휘, 문장 이해, 듣기 이해. 형태소 인식은 나오지 않음.
- D 기본: 사실·추론 문항. 평가·판단과 두 글 비교는 나오지 않음.

## 4. 연구 확장 ON 확인

각 경로를 새로 시작하며 해당 체크박스를 켠다.

### B

`B 디지털 읽기 연구 확장 실시`를 켜면 연결글 낭독 뒤에 다음이 나온다.

- 단어·비단어 판단: 350ms 표시 후 F/J 또는 버튼 응답
- 문장 참·거짓 묵독: 제한 시간 과제

화면 제목에 `(연구 확장)`이 보여야 한다.

### C

`C 형태소 인식 심화 과제 실시`를 켜면 어휘·문장·듣기 뒤에 `형태소 인식 (심화 연구 확장)`이 나온다.

### D

`D 고차 문해 연구 확장 실시`를 켜면 기본 사실·추론에 평가·판단 문항과 두 글 비교 문항이 추가된다.

## 5. 전체 흐름의 경로 화면

첫 화면에서 `읽기 확인 시작`으로 들어가 선별을 마친 뒤 경로 화면을 본다.

- 기본 하위검사: `핵심 후보 · 실시`
- 꺼 둔 확장: `연구 확장 · 선택 안 함`
- 켠 확장: `연구 확장 · 별도 채점`

`핵심 후보`는 표준화 완료가 아니라 현재 핵심 청사진에 속한 후보라는 뜻이다.

## 6. 결과 분리 확인

1. 확장을 켠 검사까지 완료한다.
2. 결과지에서 `참여자용 쉬운 결과`를 연다.
3. 참여자용에는 핵심 후보 결과만 합산되고, 연구 확장은 핵심 점수에 섞이지 않아야 한다.
4. `연구자용 상세`을 연다.
5. 확장 결과는 `연구 확장 · 별도 결과` 또는 `연구 확장 · 별도 해석`으로 표시되어야 한다.
6. 확장 점수가 낮아도 그 값만으로 `다음 단계 안내`의 추가 검사 권고가 생기지 않아야 한다.

## 7. A 청사진 기록 확인

새 A 검사를 만들고 기록 JSON을 내려받으면 다음 정보가 있어야 한다.

- `aItemBlueprint.version`: `a-decoding-blueprint-0.1`
- 네 셀 수: 실제/비단어 × 일치/음운변동 각 4
- `balanced`: `true`
- `validationStatus`: `CANDIDATE_PENDING_EXPERT_AND_PILOT`

이 기록은 구조 균형을 확인한 것이며 문항의 표준화 완료를 뜻하지 않는다.

## 8. 자동 검사

터미널에서 `npm run check`를 실행한다. 마지막에 v0.9의 핵심/확장 분리와 문서 검사가 통과해야 한다. 이 자동 검사는 코드 경로와 명칭을 확인하지만 실제 참가자의 이해도, 문항 타당도, 규준을 대신하지 않는다.
