# v0.15 로컬 검증 매뉴얼

목적: 코드를 읽기 전에 이번 보강이 실제 화면과 저장 자료에 반영됐는지 확인한다.  
원칙: 눈으로 볼 수 있는 항목과 자동 검사 항목을 구분한다. 커밋·푸시 전 이 문서를 한 번 완주한다.

## 0. 실행 준비

PowerShell에서 저장소 폴더로 이동한 뒤 실행한다.

```powershell
cd C:\LDW\graduate_research\korean-reading-assessment
npm start
```

브라우저에서 `http://localhost:8080`을 연다. 이미 8080을 쓰고 있다면 해당 서버 화면을 먼저 새로고침하고, 이전 코드가 보이면 터미널에서 `Ctrl+C`로 끈 뒤 다시 `npm start`한다. Chrome 개발자 도구를 열었으면 `Network → Disable cache`를 켜고 `Ctrl+Shift+R`로 강력 새로고침하면 캐시 혼동을 줄일 수 있다.

## 1. 버전과 첫 화면

경로: 처음 화면

- [ ] 오른쪽 위 배지가 `연구용 프로토타입 v0.15.0`이다.
- [ ] 가장 큰 행동은 `읽기 확인 시작` 하나다.
- [ ] A~D는 기본 흐름을 설명하고, 모듈별 실행은 `연구자용 도구` 안에 있다.
- [ ] `예시 채점 기록 불러오기`, 결과지, TTS 비교 같은 개발 기능이 참여자 주 행동과 시각적으로 경쟁하지 않는다.

합격 기준: 처음 보는 사람이 “읽기 확인을 시작하는 화면”임을 한 문장으로 설명할 수 있고, 연구자 도구를 열기 전에는 기술 사양이 보이지 않는다.

## 2. 정보 입력과 환경 확인

경로: `읽기 확인 시작` → 참여자 코드 입력 → `검사 환경 확인으로 이동`

- [ ] 참여자에게는 목적·준비 행동 중심 문구가 보인다.
- [ ] `음성인식 모델 준비 중` 때문에 다음 단계가 막히지 않는다.
- [ ] 화면 보정은 `ID-1 카드`, `100 mm 자`, `보정 없이 진행` 중 고를 수 있다.
- [ ] 왜 보정하는지 “기기마다 같은 자극 크기에 가깝게 맞추기 위해서”라는 설명이 있다.
- [ ] `화면·글꼴·대비·음원 상태`는 접힌 `연구자용 환경 기록` 안에 있다.
- [ ] 마이크 점검을 끝내면 `환경 확인 완료`가 활성화된다.

주의: 카드/자 보정은 물리 크기를 맞추는 보조 장치다. 시거리·시력·운영체제 배율을 자동으로 통제하는 장치는 아니다.

## 3. A 모듈 확인

경로: 처음 화면 → 연구자용 도구 → `A 글자·소리/해독`

정보 입력의 연구자 설정에서 필요한 확장 과제를 켠 뒤 진행한다.

- [ ] 검사 화면에 `비음화`, `비단어`, 문항 ID 같은 연구자 태그가 기본적으로 보이지 않는다.
- [ ] 연구자 정보 보기를 켰을 때만 태그가 나타난다.
- [ ] 연습 문제에서는 매 문항 같은 방식으로 정오 피드백을 준다.
- [ ] `연습 끝 / 본검사 시작` 경계를 지난 뒤 본검사에서는 `맞았어요`가 나오지 않는다.
- [ ] 스크롤·버튼 반응이 멈추지 않고, 검사 중 Whisper 다운로드가 시작되지 않는다.
- [ ] 실제단어와 비단어가 2음절이며, 비단어가 `두버·머자·바너·우덩·덕문·말논·텥이·덥한`으로 바뀌었다.

자동으로만 확인되는 것: 비단어 8개가 국립국어원 2023 기초어휘 전체표와 충돌하지 않으며, 짝 실제단어와 음절·받침·규칙이 일치한다. 이는 `npm run check`와 연구자 결과지의 `디지털 근거·제시 품질 감사`에서 확인한다.

## 4. B 모듈 45초 낱말 확인

경로: 처음 화면 → 연구자용 도구 → `B 읽기 유창성`

- [ ] 45초 낱말 화면에 들어와도 시작 전에는 녹음·시간 측정이 시작되지 않는다.
- [ ] 목록은 5열×12행이고 60개가 스크롤 없이 한 화면에 보인다.
- [ ] 화면이 너무 작아 일부가 가려지면 시작 버튼을 눌렀을 때 검사 시작을 막고 해결 방법을 알려준다.
- [ ] 정상 크기에서는 시작 뒤 45초에 자동 종료된다.
- [ ] 시작 후 스크롤, 다른 탭 이동, 창 크기 변경 중 하나를 일부러 하면 “실시 조건이 바뀌어 점수에서 제외”가 보인다.
- [ ] 제외된 경우에도 원음성은 보존된다는 문구가 보인다.

다시 정상 실시한 뒤 결과지에서 다음을 확인한다.

- [ ] 목록형이 `B-WE-A`, `B-WE-B`, `B-WE-C` 중 하나로 표시된다.
- [ ] 목표 45초와 실제 초·오차(ms)가 같이 나온다.
- [ ] 유효/무효가 0점과 구분된다.

참여자 코드가 같으면 같은 목록형을 받고, 코드를 바꾸면 다른 형이 배정될 수 있다. 이는 무작위처럼 보이지만 재현 가능한 고정 배정이다.

## 5. B 디지털 연구 확장 확인

경로: B 모듈 정보 입력 → 연구자 설정 → `디지털 읽기 연구 확장` 켜기

- [ ] 단어·비단어 판단 첫 자극은 화면 진입 즉시 사라지지 않고 시작 행동 뒤 제시된다.
- [ ] F/J를 눌러도 다음 문항에서 페이지가 위로 튀지 않는다.
- [ ] 본검사에는 정오 피드백이 없고 연습에만 있다.
- [ ] 결과지에서 이 과제가 `연구 확장`으로 표시되고 B 핵심 점수와 합쳐지지 않는다.

반응시간 200ms 미만 또는 5,000ms 초과는 연구 품질 플래그가 붙는다. 이 값은 한국어 규준이나 장애 판정 기준이 아니라 ROAR형 웹검사에서 비정상 응답을 따로 살펴보기 위한 연구용 범위다.

## 6. C·D 화면과 자동 감사

경로: 처음 화면 → 연구자용 도구 → C 또는 D

- [ ] 지문은 왼쪽 정렬이고 한 줄 폭이 지나치게 길지 않다.
- [ ] 선택지는 충분한 클릭 영역을 가지며, 좁은 화면에서는 한 열로 바뀐다.
- [ ] C 기본에는 어휘·문장·듣기 이해가 나오고, 형태소는 연구자 설정을 켰을 때만 나온다.
- [ ] 형태소 과제는 단순히 같은 글자를 찾는 문제가 아니라 합성어/파생어 결합·분해다.
- [ ] D 기본에는 사실·추론이 나오고 평가·두 글 비교는 연구 확장 설정 때만 나온다.
- [ ] 연구 확장 결과가 핵심 후보 결과와 분리된다.

선택형 문항의 지문 길이·어휘등급 가용률·문법 표지·선택지 길이 단서는 참여자 화면이 아니라 연구자 결과지 품질 감사에서 확인한다.

## 7. 결과지 확인

빠른 경로: 처음 화면 → `예시 채점 기록 불러오기` → 결과 → `전문 결과지 보기`

### 참여자용

- [ ] 쉬운 영역명과 이번 후보 문항의 맞힌 수를 먼저 보여준다.
- [ ] 또래보다 잘함/어려움, 진단, 백분위를 말하지 않는다.
- [ ] 분석 전과 점수 제외가 0점과 구분된다.
- [ ] 다음에 무엇을 확인할지 쉬운 말로 알려준다.

### 연구자용

- [ ] `디지털 근거·제시 품질 감사` 표가 있다.
- [ ] A 실제단어 메타데이터 수와 A 비단어 기본조건 `8/8`이 보인다.
- [ ] 비단어 8개는 철자 음절 bigram 대리지표가 연결되고, 발음 말뭉치 기반 음운확률은 대기로 구분된다.
- [ ] B를 실시했다면 목록형·화면조건·실측시간이 보인다.
- [ ] C·D를 실시했다면 절 감사 수와 자동 검토 문항 수가 보인다.
- [ ] 자동 감사가 타당도·규준을 뜻하지 않는다는 한계 문구가 있다.

## 8. TTS 확인

경로: 연구자용 도구의 TTS 비교 또는 듣기 문항

- [ ] 같은 세션에서는 선택된 한국어 음성명과 속도가 고정된다.
- [ ] 재생시간과 추정 SPM이 기록된다.
- [ ] 음성이 없거나 재생에 실패하면 듣기 문항 응답을 열지 않는다.
- [ ] 현재 브라우저/운영체제에 따라 목소리가 달라질 수 있음을 확인한다.

현재 고정 음원은 등록되지 않았다. 따라서 음질이 마음에 들지 않는 것은 이번 코드에서 숨기지 않은 실제 잔여 과제다. 후보 파일을 준비한 뒤 다음 형식으로 평가한다.

```powershell
node tools/tts_candidate_benchmark.mjs <후보평가.json>
node tools/validate_audio_manifest.mjs
```

결과가 `READY_FOR_FIXED_MANIFEST`이고 사용권·해시·청취 승인이 기록된 후보만 manifest에 넣는다.

## 9. 자동 검사

서버를 별도 터미널에 켜 둔 상태여도 실행할 수 있다.

```powershell
npm run check
```

합격 기준은 프로세스 종료 코드 0과 마지막 줄의 다음 메시지다.

```text
통과: v0.15 홈 렌더링 및 콘텐츠 폭 행렬 320px, 768px, 1440px에서 60개·5열×12행·가로 넘침 없음
```

TTS는 다음처럼 나오는 것이 현재 정상이다.

```text
통과(대기): MANIFEST_READY_ASSETS_PENDING · 고정 음원 0개
```
